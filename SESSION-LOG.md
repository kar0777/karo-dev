# SESSION-LOG — что делали 01–02.09.2026

Рабочая сессия по принципу «рабочей лошадки»: циклы **большой кусок → тесты →
браузер → API → деплой**, по кругу. За сессию — 5 циклов, 9 коммитов, все
задеплоены через push в `main` → Vercel, CI зелёный.

## Циклы

### Цикл 1 — CLI-агенты: «терминалы по лицензии» (`1feb210`)

Каталог сторонних терминальных AI-агентов, которых можно поставить **в сэндбокс
Karo** или **на свою машину**. Karo не распространяет ничего: команды установки
— официальные, от вендоров; проприетарные инструменты (Claude Code) логинятся
своим аккаунтом/лицензией в терминале.

- Каталог (сид, 8 штук): Claude Code, Codex CLI, Gemini CLI, Aider, OpenCode,
  Crush, Qwen Code, Goose — с лицензией и способом авторизации на карточке.
- Схема: `cli_tools` + `sandbox_cli_installs` (миграция 0007, сиды апсертятся
  по slug и не включают выключенное админом).
- API: `GET /api/cli-tools` (опц. `?sandboxId=` — со статусом установки),
  `POST /api/cli-tools/[slug]/check` (проба `command -v bin && bin --version`
  через exec песочницы), `POST /api/cli-tools/[slug]/launch` (пишет в
  песочницу лаунчер-скрипт 0600, опционально вшивая ключ юзера из BYOK-сейфа
  — ключ расшифровывается только на сервере, в браузер и историю терминала не
  попадает), админ-CRUD `/api/admin/cli-tools` с аудитом.
- UI: диалог «CLI agents» в тулбаре терминала воркспейса. Install печатает
  команду в отдельную именованную сессию (прогресс видно живьём), через 4 с
  авто-чек переворачивает бейдж в «Installed · версия». Launch открывает
  сессию с именем тулза и командой запуска. Вкладка «On my machine» —
  команды под macOS/Linux/Windows с копированием.
- Админка: `/admin/cli-tools` — вкл/выкл (скрывает тулз платформенно без
  деплоя), правка, добавление своего.
- Mock-провайдер научился «ставить» npm/pip-пакеты и отвечать на
  `command -v` / `--version`, чтобы вся фича работала в демо-режиме.
- Попутный фикс: **метрики-поллер крутится тугим циклом** (~30 запросов/сек
  до упора в rate-limit) — эффект зависил от всего объекта `sandbox`, а каждый
  успешный опрос менял ссылку → эффект перезапускался мгновенно. Оставлены в
  зависимостях только `sandbox?.id` и `sandbox?.status`.

Проверено: curl-прогон install→check→launch, браузером из диалога, e2e
`tests/e2e/cli-agents.spec.ts`.

### Цикл 2 — MCP-инструменты в агенте (`f82f73a`)

До этого MCP-серверы были полноценным разделом UI, но агент их **не видел**:
промпт строился с `mcpTools: []`, а в цикле знали только встроенные тулы.

- Рантайм грузит включённые серверы команды через существующий пул менеджера
  и подмешивает неймспейсованные определения `mcp__<сервер>__<тул>` (кап 40
  на прогон) в список инструментов.
- Деструктивные тулы (по эвристике + флагу сервера «requireApproval») идут
  через тот же flow `approval.required`, что и встроенные; эндпоинт
  `/api/runs/[runId]/approve` пере-резолвит маршрут и исполняет через
  `callTool` — выключенный между паузой и одобрением сервер честно отвечает
  «tool unavailable».
- Вызовы персистятся с `source: 'mcp'`, проходят ту же редакцию секретов,
  обрезку и метринг. Ask-режим и проекты без `useMcpTools` — поведение без
  изменений.
- Тесты: юнит 3/3 (approval-гейт, хэнд-офф, ошибки) + интеграция 4/4 против
  **настоящего** stdio MCP-сервера (discovery, неймспейсинг, деструктив-роутинг,
  вызов). Живой e2e: build-прогон на Qwen3-Coder вызвал
  `mcp__echo_server__echo` и доложил ответ.

### Цикл 3 — живучесть mock-сэндбоксов (`30097c6`)

Три бага, всплывших при рестарте dev-сервера посреди работы:

1. **Зомби-сэндбоксы.** Рестарт процесса стирал все симулированные машины, а
   строки в БД оставались `running` — терминалы вечно «Reconnecting…», exec
   отвечал «no longer exists». Фикс: `rehydrateProvider` перед каждой
   операцией скармливает провайдеру форму машины из строки БД
   (`rememberSnapshot`), и симулятор пересобирает её.
2. **Разделённые очереди.** Очереди терминального ввода жили в модульной
   карте, когда остальной статор уже переехал в `globalThis`. Dev-HMR держит
   по инстансу модуля на роут — input и stream писали/читали разные карты и
   «не слышали» друг друга. Очереди переехали в общий стор.
3. **Игнор abort в `queue.next()`.** Отключение клиента оставляло генератор
   стрима висеть до следующего чанка — `finally` с флашем scrollback не
   выполнялся, и хвост вывода терялся (флаш срабатывал, только если после
   паузы >3 с приходили новые байты). Теперь цикл гонит `queue.next()` с
   abort-промисом — при закрытии хвост гарантированно пишется в
   `terminal_sessions.scrollback`.

Проверено рестартами сервера прямо в процессе работы: реконнект без
«Reconnecting…», вывод команды остаётся в БД после отключения.

### Цикл 4 — админка: quick actions + воскрешение `/admin` (`416ba38`)

- На Overview добавлены три кнопки идемпотентного обслуживания: **Run
  maintenance tick** (`/api/cron/tick`), **Sleep idle sandboxes**
  (`/api/admin/sandboxes/sweep`), **Sync model catalogue**
  (`/api/admin/models/sync`) — с тостами-результатом и `router.refresh()`.
  Те же job'ы, что и по крону, но доступные оператору в один клик.
- Попутно найдено: **вся страница `/admin` была мертва** — запрос
  platform-counts передавал сырой `Date` внутрь `sql\`\`` шаблона drizzle,
  postgres.js отказывался его сериализовать (`ERR_INVALID_ARG_TYPE`), и любой
  рендер падал 500-й за error boundary. Фикс — ISO-строка вместо Date
  (`gte()/lte()` не страдали: типизированные хелперы сериализуют сами).

## Как проверить руками

1. Dev-сервер: `APP_URL=http://localhost:3001 npx next dev -p 3001`
   (WSL должен быть разбужен — см. Окружение).
2. CLI-агенты: воркспейс любого проекта → вкладка Terminal → кнопка
   «CLI agents» → Install у любого тулза → через ~5 с бейдж «Installed» →
   Launch откроет сессию с именем тулза.
3. MCP: в проекте CLI Lab уже подключён сервер «Echo Server». Отправить
   агенту: «Use the MCP echo tool with text …» — в прогоне появится тул
   `mcp__echo_server__echo` с source=mcp.
4. Админка: `/admin` → три кнопки обслуживания под заголовком; `/admin/cli-tools`
   — каталог.
